
## 2024-05-27 - [Predictable Temp Files & Resource Leak in PDF Loaders]
**Vulnerability:** Discovered two temporary file related vulnerabilities in PDF processing: 1. Predictable, hash-based temporary file names were generated (`temp_{hash}.pdf`), causing file collision risks and potential local file injection vulnerabilities. 2. `PDFHelper.ask` removed temporary files outside of a try/finally block, meaning failures during `PyPDFLoader.load()` would result in abandoned temp files and disk space exhaustion (DoS).
**Learning:** Manual filename generation is dangerous. Even hashing file contents is predictable when handling identical files, risking race conditions across users. Also, file-path-based document loaders (`PyPDFLoader`) can be brittle; failures in parsing complex PDFs often throw exceptions that interrupt linear execution flows, meaning cleanup must be heavily guarded.
**Prevention:** Always use `tempfile.NamedTemporaryFile` for generating random, secure file paths. When using third-party loaders that require a local file path (`delete=False`), always wrap the loader call in a `try...finally` block, checking for the existence of `temp_file_path` before `os.unlink()` to ensure guaranteed cleanup.
